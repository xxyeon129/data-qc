# 로컬 코드 리뷰

현재 브랜치의 변경사항을 리뷰하고 결과를 마크다운 파일로 생성합니다.

**사용법:** `/review` 또는 `/review <추가 지시사항>`

추가 지시사항: $ARGUMENTS

---

## 리뷰 절차

### 1단계: 변경사항 파악

1. `git fetch origin dev` 로 원격 dev 브랜치를 최신화
2. `git branch --show-current` 로 현재 브랜치명을 확인하고 이슈 번호를 추출한다 (예: `2232` → `2232`)
3. `git log origin/dev..HEAD --oneline` 으로 전체 커밋 이력을 확인한다
4. 이슈 번호에 해당하는 커밋에서 변경된 파일만 리뷰 대상으로 추출한다:
   ```bash
   git log origin/dev..HEAD --name-only --format="" --grep="이슈번호" | sort -u
   ```
5. 리뷰 대상 파일들의 diff를 확인한다:
   ```bash
   git diff origin/dev..HEAD -- <리뷰대상파일1> <리뷰대상파일2> ...
   ```

> **주의**: `git diff origin/dev..HEAD` 를 파일 필터 없이 실행하면, 다른 이슈의 커밋이 이 브랜치에 포함된 경우 관련 없는 변경분까지 리뷰 대상에 포함된다.
> 반드시 `--grep` 으로 현재 브랜치 이슈 번호에 해당하는 커밋만 필터링하고, 해당 커밋이 변경한 파일만 리뷰한다.
> 로컬 `dev`가 아닌 `origin/dev`를 기준으로 비교해야 다른 브랜치의 변경분이 포함되지 않는다.

### 2단계: 변경 파일 전체 코드 읽기

diff에 나타난 모든 변경 파일의 **전체 코드**를 읽어 맥락을 파악한다. diff만으로는 주변 코드와의 관계를 이해할 수 없으므로, 반드시 파일 전체를 읽을 것.

### 3단계: 코드 리뷰 수행

`docs/CODE_REVIEW_GUIDE.md` 파일을 읽고 해당 기준으로 리뷰를 수행한다.

**리뷰 관점:**

리뷰 결과물은 "코드를 보지 않은 사람도 이 작업이 왜 필요했고, 무엇이 바뀌었으며, 어떻게 동작하는지 이해할 수 있을 정도"로 서술한다.

#### 1. 작업 배경 & 목적
- 이 변경이 왜 필요했는가? (문제 상황, 요구사항, 개선 동기)
- 어떤 기능을 추가/수정/삭제했는가?

#### 2. 구현 방식 설명
- 핵심 로직을 단계별로 설명한다 (예: "① 파일 업로드 → ② 파싱 → ③ DB 저장")
- 중요한 알고리즘이나 데이터 흐름을 명확히 서술한다
- 새로 도입한 패턴이나 라이브러리가 있다면 이유와 함께 설명한다

#### 3. 주요 변경 포인트
- 변경된 파일별로 "무엇이 바뀌었는지" 한 줄 요약
- 특히 기존 코드와 달라진 점, 삭제된 이유가 있는 코드를 명시한다

#### 4. 데이터 흐름 & 연관 관계
- 변경된 코드가 시스템의 어느 부분에 위치하는지 (프론트 → API → 서비스 → DB 중 어디)
- 다른 모듈/컴포넌트와 어떻게 연결되는지 간략히 설명한다

#### 5. 잠재적 리스크 & 주의사항
- 엣지 케이스나 예외 처리가 미흡한 부분
- 성능, 보안, 유지보수 측면에서 주의할 점
- 향후 변경 시 영향을 받을 수 있는 부분

#### 6. 개선 제안 (선택)
- 코드 가독성, 구조, 네이밍 등에 대한 구체적인 개선 의견
- "이렇게 바꾸면 더 낫다"는 대안 코드를 제시할 수 있으면 함께 작성한다


### 4단계: 리뷰 결과 마크다운 파일 생성

리뷰 결과를 `docs/review-{브랜치명}.md` 파일로 생성한다.
브랜치명에서 `#`은 제거하고 사용한다. (예: 브랜치 `#2219` → `docs/review-2219.md`)

**파일 형식:**

```markdown
# 코드 리뷰: {브랜치명}

- 리뷰 일시: {오늘 날짜}
- 대상 브랜치: {브랜치명}
- 변경 파일 수: {N}개

## 변경 사항 요약

(변경된 기능/목적을 간단히 요약)

## 리뷰 결과

### {파일경로}

- **L{라인번호}**: 리뷰 내용
  ```typescript
  // 해당 코드 스니펫 (필요 시)
  ```

(파일별로 반복)

## 총평

(전체적인 코드 품질 평가 및 권장사항)
```

**주의사항:**
- 발견 사항이 없으면 "리뷰 결과 특이사항 없음"으로 작성
- 추가 지시사항이 있으면 해당 내용을 우선적으로 반영
